# REST API

Базовый URL: `http://localhost:8080/api/loans`. JSON, даты в формате `YYYY-MM-DD`, идентификаторы — UUID. Денежные значения передаются числом или десятичной строкой с точкой; в ответе — JSON number. Сервер рассчитывает деньги через BigDecimal.

| Метод | Путь | Действие |
| --- | --- | --- |
| GET | `/api/loans` | Список кредитов с текущим остатком |
| POST | `/api/loans` | Создать кредит; 201 и заголовок Location |
| GET | `/api/loans/{id}` | Параметры, итоги, следующий платёж и история |
| GET | `/api/loans/{id}/forecast` | Обычный и альтернативный графики |
| POST | `/api/loans/{id}/payments` | Записать следующий месячный платёж; 201 |
| DELETE | `/api/loans/{id}/payments/{paymentId}` | Отменить последнюю запись; 204 |

## Создание

```json
{
  "name": "Кредит на ремонт",
  "principal": 100000.00,
  "annualRate": 12,
  "monthlyPayment": 10000.00,
  "firstPaymentDate": "2026-11-01"
}
```

Все поля обязательны. Название — до 80 символов. Сервер заранее проверяет, что кредит будет погашен с заданным платежом. Возвращает `LoanDetail`, где `id` используется в следующих запросах.

## Запись платежа

```json
{
  "requestId": "51bb0470-21c0-4e94-b1e8-05b0a33154f2",
  "amount": 12000.00
}
```

Для нового платежа создай новый UUID. При повторной отправке **того же** платежа используй прежний `requestId`: сервер вернёт ту же запись с 201, не создавая дубль. Тот же ключ с другой суммой даст 409. Уникальность ключа ограничена одним кредитом.

Первая запись в приведённом примере распределяется на 1 000 ₽ процентов и 11 000 ₽ основного долга; остаток — 89 000 ₽. Поля ответа: `id`, `number`, `date`, `amount`, `interest`, `principal`, `balance`, `recordedAt`.

`date` назначается сервером по следующему периоду графика. `recordedAt` — время фактического создания записи, например `2026-10-22T10:30:00Z`. Произвольную дату платежа эта модель не принимает.

При записи или отмене сервис блокирует строку соответствующего кредита (`SELECT ... FOR UPDATE`) внутри транзакции. Уникальные ограничения БД защищают `(loan_id, request_id)` и `(loan_id, installment_number)`.

## Прогноз

```http
GET /api/loans/{id}/forecast?extraMonthly=2000&oneTimeExtra=10000
```

Оба параметра необязательны, по умолчанию 0. Отрицательные значения запрещены. Ответ:

- `baseline`: план с обычным платежом от текущего остатка;
- `scenario`: план с указанными доплатами;
- `interestSaved`: разница будущих процентов;
- `monthsSaved`: разница количества будущих месяцев.

Каждый план содержит `months`, `payoffDate`, `totalInterest`, `totalPayment`, `rows`. В строке: `number`, `date`, `openingBalance`, `payment`, `interest`, `principal`, `balance`. Нумерация продолжается после истории. У погашенного кредита `rows` пуст и `months` равен 0; `payoffDate` — дата последнего расчётного платежа.

Прогноз не сохраняется. После обновления страницы интерфейс показывает сценарий без доплат.

## Отмена

Передавай точный `paymentId` последней записи. Если она уже не последняя, сервер вернёт 409, вместо отмены другой записи. Если история пуста — 404. После удаления старый `requestId` больше не хранится; для исправленного платежа используй новый UUID.

## Ошибки

`Content-Type: application/problem+json`.

```json
{
  "type": "about:blank",
  "title": "Unprocessable Content",
  "status": 422,
  "detail": "Платёж должен покрывать проценты за месяц: 1000.00 ₽."
}
```

| Код | Причина |
| --- | --- |
| 400 | Неверный JSON, UUID, формат числа/даты, обязательное поле или ограничение поля |
| 404 | Кредит не существует или история для отмены пуста |
| 409 | Ключ уже использован для другой суммы, отменяется не последний платёж, конфликт данных |
| 422 | Неподходящий платёж, переплата, долг уже погашен, неверные доплаты или непогашаемый график |

При валидации полей ответ 400 содержит объект `errors`: имя поля → сообщение. Подробности SQL и стек исключения клиенту не выдаются.
