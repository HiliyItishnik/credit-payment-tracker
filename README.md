# Платёж · Credit Payment Tracker

Учебный проект на Java: трекер кредитов с историей платежей, графиком остатка долга и прогнозом досрочного погашения. Подходит для портфолио и изучения Spring Boot, REST API, JPA и PostgreSQL.

**Стек:** Java 21 · Spring Boot 4.1.1 · Spring MVC · Spring Data JPA · PostgreSQL 17 · Flyway · Maven · JUnit · HTML/CSS/JavaScript.

## Возможности

- Несколько кредитов: название, начальная сумма, годовая ставка, ежемесячный платёж, дата первого платежа.
- График по месяцам: платёж, проценты, погашение основного долга, остаток.
- История фактических сумм платежей, сохранённая в PostgreSQL.
- Прогноз досрочного погашения с регулярной и разовой доплатой: новый срок и экономия на будущих процентах.
- Отмена последнего платежа с восстановлением остатка.
- Защита от повторной записи платежа по UUID запроса, транзакции и блокировка строки кредита.
- Адаптивный интерфейс на русском, без сборщика JavaScript и внешних CDN.
- Миграция схемы БД, unit-тесты расчётов, интеграционные тесты REST API и GitHub Actions.

Приложение рассчитано на одного пользователя и запускается на `127.0.0.1`. Авторизация в эту версию не входит.

## Быстрый запуск

Нужны **JDK 21**, **Maven 3.6.3+** и **Docker с Docker Compose**. IntelliJ IDEA может использовать встроенный Maven, поэтому для запуска через IDE устанавливать Maven отдельно необязательно.

Из папки проекта:

```bash
docker compose up -d --wait
mvn spring-boot:run
```

Открой **http://localhost:8080**. Кнопка «Новый кредит» → «Подставить пример» заполнит форму; данные сохранятся только после нажатия «Создать кредит».

Первый запуск Maven скачивает зависимости из интернета. Если порт 5432 занят другим PostgreSQL, смотри раздел настроек ниже.

Остановка приложения: `Ctrl+C` или Stop в IDE. Остановка базы с сохранением данных:

```bash
docker compose down
```

Данные находятся в Docker volume `postgres_data`. Команда `docker compose down -v` удаляет этот том и все кредиты — она нужна только для намеренного сброса базы.

## Запуск в IntelliJ IDEA

1. Распакуй архив и открой папку `credit-payment-tracker` через **File → Open**. Если IDE предлагает вариант, выбери Maven project.
2. В **File → Project Structure → Project SDK** укажи JDK 21. При необходимости скачай JDK через **Download JDK**.
3. Дождись импорта `pom.xml`. В окне Maven нажми Reload All Maven Projects, если зависимости не подтянулись.
4. В Terminal из корня проекта выполни `docker compose up -d --wait`.
5. Открой `src/main/java/dev/portfolio/credittracker/CreditTrackerApplication.java` и запусти `main` зелёной кнопкой.
6. Перейди на http://localhost:8080.

Если команда `mvn` не найдена в терминале, это не мешает запуску через `main`. Для Maven-команд используй окно Maven → Execute Maven Goal, например `clean verify`. Проверь, что JDK импортера и Maven Runner также установлен на 21.

## Сборка JAR

```bash
mvn clean verify
java -jar target/credit-payment-tracker-1.0.0.jar
```

Перед запуском JAR база должна быть доступна. `clean verify` по умолчанию запускает только unit-тесты и не требует базы. Интеграционные тесты включаются отдельным профилем.

## Настройки базы

| Переменная приложения | Значение по умолчанию |
| --- | --- |
| `DB_URL` | `jdbc:postgresql://localhost:5432/credit_tracker` |
| `DB_USERNAME` | `tracker` |
| `DB_PASSWORD` | `tracker_local` |
| `PORT` | `8080` |

Для локального примера Compose уже настроен с такими же значениями. Пароль `tracker_local` — открытый пароль демонстрационной локальной БД.

Можно скопировать `.env.example` в `.env` и настроить Compose. **Spring Boot не читает `.env` автоматически**: изменённые `DB_URL`, `DB_USERNAME` и `DB_PASSWORD` нужно отдельно передать в переменных окружения конфигурации запуска IntelliJ IDEA. Файл `.env` исключён из Git.

Например, для порта 5433 задай `DB_PORT=5433` в `.env`, а приложению — `DB_URL=jdbc:postgresql://localhost:5433/credit_tracker`. `DB_NAME` и `DB_PORT` используются Compose; приложение получает имя и порт через `DB_URL`.

Переменные `POSTGRES_*` из Compose применяются только при первом создании базы в пустом Docker volume. Изменение `.env` не меняет пароль уже существующего пользователя PostgreSQL.

Если PostgreSQL установлен без Docker, создай роль и базу через psql или pgAdmin от имени администратора:

```sql
CREATE ROLE tracker LOGIN PASSWORD 'tracker_local';
CREATE DATABASE credit_tracker OWNER tracker;
```

Таблицы вручную создавать не нужно: **Flyway** применяет `V1__create_loans_and_payments.sql`, затем Hibernate проверяет соответствие схемы сущностям (`ddl-auto: validate`).

## Как считается кредит

Это модель кредита с **постоянной ставкой и заданным фиксированным месячным платежом**. Платёж вводит пользователь; аннуитетный платёж по сроку не вычисляется.

```text
проценты = остаток × годовая ставка / 1200
основной долг в платеже = платёж − проценты
новый остаток = старый остаток − основной долг в платеже
```

Проценты округляются до двух знаков через `BigDecimal` и `RoundingMode.HALF_UP`, один раз после деления. Последний плановый платёж уменьшается до `остаток + проценты`.

Пример: долг **100 000 ₽**, ставка **12%**, платёж **10 000 ₽**. За первый месяц: **1 000 ₽** процентов, **9 000 ₽** основного долга, остаток **91 000 ₽**. Проценты следующего месяца — **910 ₽**.

### История и даты

- Одна запись в истории — общая сумма за **один следующий расчётный месяц**. Несколько переводов за один месяц нужно объединить в одну запись.
- Фактическая сумма может отличаться от обычного платежа, но должна покрывать проценты. Платёж ровно на сумму процентов допускается: долг не уменьшается.
- Переплата сверх `остаток + проценты` отклоняется с объяснением точной суммы полного погашения.
- Расчётные даты привязаны к первой: 31 января → 28/29 февраля → 31 марта. Дни выходных не учитываются.
- `recordedAt` хранит реальное время внесения записи в UTC, `date` — расчётную дату. Текущее календарное число не влияет на модель.
- Можно отменить только последнюю запись. Для корректировки более раннего месяца последовательно отмени последующие записи и внеси исправленные суммы заново.

### Досрочное погашение

Ежемесячная доплата добавляется ко всем будущим платежам. Разовая — только к следующему. Сокращается срок, обычный платёж сохраняется. Экономия сравнивает будущие проценты **от текущего остатка**; уже уплаченные проценты не включаются. Прогноз не меняет БД.

### Ограничения

Начальная сумма: 0,01–100 000 000 ₽. Годовая ставка: 0–100%, до четырёх знаков после запятой. Один платёж и каждая доплата: до 1 000 000 000 ₽, до двух знаков. Первая дата: 1900–2200 год. Обычный платёж обязан уменьшать долг и погашать его не более чем за 600 будущих месяцев.

Ежедневное начисление процентов, комиссии, страховки, просрочки, штрафы и изменение ставки не моделируются. График конкретного банка может отличаться. В интерфейсе есть отдельная страница с этими допущениями.

## Структура

| Путь | Назначение |
| --- | --- |
| `domain/AmortizationCalculator.java` | Расчёт графика и распределение платежа без обращений к БД |
| `loan/LoanService.java` | Бизнес-сценарии, транзакции, история, повторные запросы |
| `loan/Loan.java`, `loan/Payment.java` | JPA-сущности |
| `loan/*Repository.java` | Доступ к PostgreSQL через Spring Data JPA |
| `api/LoanController.java` | REST-эндпоинты |
| `api/LoanDtos.java` | Контракты запросов и ответов, валидация |
| `api/ApiErrorHandler.java` | Ошибки в формате Problem Detail |
| `resources/db/migration/` | Версионируемая схема БД |
| `resources/static/` | HTML, CSS, JavaScript, SVG-график |

Слои: браузер → контроллер → сервис → калькулятор / репозитории → PostgreSQL. Калькулятор не зависит от JPA или веб-контроллеров. Сущности не выдаются напрямую в JSON.

## Тесты

```bash
mvn test
```

Unit-тесты проверяют расчёт процентов, округление, нулевую ставку, конец месяца, последний платёж, досрочное погашение, неамортизируемый долг и сохранение денежных сумм.

Для интеграционных тестов создай **отдельную** базу один раз:

```bash
docker compose up -d --wait
docker compose exec db createdb -U tracker credit_tracker_test
mvn -Pintegration verify
```

Профиль `integration` использует `TEST_DB_URL`, `TEST_DB_USERNAME`, `TEST_DB_PASSWORD` (по умолчанию локальная БД `credit_tracker_test`, роль `tracker`, пароль `tracker_local`). При изменённых параметрах передай их через окружение IDE/терминала. Тесты очищают таблицы; перед очисткой проверяют, что имя БД заканчивается на `_test`. Не направляй тесты на рабочие данные. Миграция выполняется при старте контекста, до этой проверки имени.

API-тесты проверяют создание и сохранение кредита, историю, погашение, ошибки, изоляцию кредитов, повторную и конкурентную отправку одного UUID, отмену последней записи. GitHub Actions запускает unit- и API-тесты с PostgreSQL 17 и Flyway на каждом push/PR.

Фактические результаты проверки готового архива описаны в [docs/VERIFICATION.md](docs/VERIFICATION.md).
